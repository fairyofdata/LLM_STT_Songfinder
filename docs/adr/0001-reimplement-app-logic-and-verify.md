# ADR-0001: 평가 코드에서 앱 로직을 재구현하고 원본과 대조한다

- 상태: 채택
- 결정일: 2026-10-21
- 기록: 2026-10-22 소급 작성 (근거: [연구개발 기록](../RESEARCH_LOG.md))

## 맥락
`app.py`를 import하면 OpenAI 클라이언트, Spotify OAuth 설정, FastAPI 앱이 함께 올라온다. 대량 평가에서 그 부작용과 의존성을 피하고 싶었다. 하지만 평가 코드가 앱과 다르게 동작하면 측정 자체가 무의미해진다.

## 결정
- 곡 식별 부분만 `eval/common.py`에 그대로 다시 구현한다.
  - 텍스트 경로: 요약 top-1 대 가사 top-1, 판정선 0.4, 요약 분기의 원래 코드
  - 음성 경로: 가사 top-1
- `eval/check_against_app.py`가 `app.py`를 실제로 import한다(Spotify 자격 증명에는 임시 값을 넣음). 질의 유형별 10개와 음의 대조군 90개를 원본 함수로 돌려 결과를 대조한다.

## 결과
- 처음과 마지막 확인 모두 140/140 일치했다(2026-10-21, 10-22).
- `app.py`의 식별 로직이 바뀌면 이 대조를 다시 돌려야 한다.

## 검토한 대안
- 평가 때마다 `app.py`를 import: 부작용이 크고 느리다.
- HTTP 엔드포인트 호출: 서버와 외부 키가 필요하고, 음성은 `whisper-1` 비용이 든다. 끝단 시험은 별도 과제로 남긴다.
