# ADR-0013: 검색을 모듈로 분리하고, 음성 개선 두 가지를 조건부로 넣는다

- 상태: 채택
- 결정일: 2026-10-23
- 근거: [평가 상세 「서비스 반영 후 실측」](../EVALUATION.md#서비스-반영-후-실측-searchpy), `eval/compare_impl.py`

## 맥락
평가([ADR-0012](0012-estimate-fixes-from-existing-transcripts.md))에서 두 가지 추정치가 나왔다.
- 「한국어 감지 시 일본어 재전사」로 한국인 발음 정확도가 오른다.
- 「줄 단위 조각 투표」로 여러 줄 음성 정확도가 오른다.

서비스 단계로 넘어오면서 이를 실제 코드에 넣기로 했다. 그런데 처음 그대로 넣자 텍스트 경로에서 두 가지 부작용이 나왔다.
- 띄어쓰기가 있는 긴 한 줄(주로 영어 가사)이 조각으로 나뉘면서 원문 일치가 뒤집혔다(입력 질의 기준 새로 맞음 5 대 새로 틀림 33).
- 판정선 비교에 「가장 잘 맞은 조각 점수」를 쓰자, DB에 없는 문장의 오판정이 93.3%에서 98.9%로 늘었다.

## 결정
- 식별·추천 로직을 `search.py`의 `SongIndex`로 옮긴다. `app.py`는 이를 호출만 한다. 평가 코드(`eval/compare_impl.py`)와 테스트도 같은 모듈을 쓴다.
- **조각 투표는 다음 두 조건을 모두 만족할 때만 쓴다.**
  - 질의 전체의 가사 top-1 코사인이 0.9 미만이다(`EXACT_LINE_SCORE`). 즉 어느 한 줄과도 거의 일치하지 않는다.
  - 질의가 줄 길이 조각 3개 이상으로 나뉜다(`MIN_VOTE_WINDOWS`).
  - 투표 방식: 조각별 1순위 점수에, 전체 질의 1순위를 조각 수의 제곱근만큼 가중해 더한다.
- **판정은 예전과 같이 둔다.** 판정선과 「요약 대 가사」 비교는 질의 전체의 코사인으로 한다. 투표는 곡을 고르는 데만 쓴다.
- **요약 분기는 요약 인덱스를 곡 인덱스로 바로 쓴다**(버그 수정, [ADR-0004](0004-report-bug-without-fixing.md)의 후속).
- **`/stt` 재전사:** `whisper-1`을 `verbose_json`으로 불러 감지 언어를 받는다. 한국어로 감지된 경우에만 `language="ja"`로 한 번 더 부른다. 환경 변수 `SONGFINDER_KO_TO_JA_FALLBACK=0`으로 끌 수 있다.
- **판정선 0.4는 바꾸지 않는다.** 환경 변수 `SONGFINDER_TEXT_THRESHOLD`로 뺐고, 값은 사용자 결정으로 남긴다.

## 결과
실측(같은 입력, 예전 로직 대비, 짝지은 비교):

| 항목 | 예전 → 지금 | 새로 맞음 / 새로 틀림 |
|---|---|---|
| 입력 질의 (21,953개) | 60.6% → 60.6% | 0 / 3 |
| 원어민 5줄 음성 | 47.2% → 73.9% | 121 / 1 |
| 한국인 발음 5줄 음성 | 35.6% → 69.0% | 155 / 5 |
| 요약 분기 탐침 | 0.2% → 100% | |
| DB에 없는 문장 오판정 | 93.3% → 93.3% | |

- 음성 결과는 로컬 Whisper 전사문으로 잰 것이다. 앱의 `whisper-1`에서는 재측정이 필요하다.
- 투표 조건(0.9, 3조각)은 시드 1 입력 질의로 따로 확인해 정했다. 3조각 대신 2조각부터 투표하면 음성은 0.3~0.7%p 높지만 한 줄 질의 일부가 뒤집힌다. 그래서 「한 줄 질의는 예전과 같아야 한다」를 우선했다.
- 한국어로 감지된 경우에만 STT 호출이 한 번 더 생긴다. 평가 기준으로 원어민 0.4%, 한국인 발음 35%에서 일어난다.
